## Manual QA(自動測試覆蓋不到的地方)

> 不是每個模組都需要全部勾選。沒有 UI 的純後端模組可以略過 viewport 與 UI 狀態。重點是**對著螢幕真的點過一遍**,不要只看測試輸出就收工。

### 如果這個模組有 UI

- [ ] 正常流程能完整跑完一次(從進入到完成)
- [ ] 空狀態:沒資料時畫面合理(不會是空白或破版)
- [ ] Loading 狀態:資料載入中有提示,不是卡住的錯覺
- [ ] 錯誤狀態:故意觸發錯誤(例如斷網、輸入無效),畫面能告知使用者
- [ ] 權限不足時的顯示(若模組有權限分級)
- [ ] 桌面 viewport(1280 寬以上)
- [ ] 手機 viewport(375 寬左右)
- [ ] 截圖 / 錄影證據:[填路徑或 commit 引用,或寫「無 UI 改動,不適用」]

### 如果這個模組有 API / 後端

- [ ] 正常 input 的 response 有看過(用 curl、Postman、或自動測試)
- [ ] 邊界 input(空字串、超大數字、特殊字元)不會 500
- [ ] 沒權限 / 沒登入時的 response 是預期的(401 / 403,不是 500)
- [ ] 錯誤訊息對前端開發者來說可解讀(不是純 stack trace)

### 如果這個模組碰到資料

- [ ] 重複觸發(例如重複 click submit)不會產生重複資料
- [ ] 部分失敗時不會留下髒資料(交易性 / rollback)
- [ ] migration / 改 schema 後,既有資料還能正常讀取

- 發現的問題:[列出,或寫「無」]
